# Mathematicon

## Getting started
В проекте используется [poetry](https://python-poetry.org/) (версия 2.1) для работы с зависимостями. Чтобы запустить проект, нужно:
1) Установить poetry (инструкция [тут](https://python-poetry.org/docs/#installing-with-pipx)) - рекомендуется через pipx.
2) Установить python 3.9, если такая версия еще не установлена.
3) Выполнить:
    ```shell
    poetry env actitvate
    ```
   Команда создаст папку под виртуальное окружение (`.venv`) и выведет в консоль **команду для его активации**. По умолчанию poetry создает виртуальные окружения в своей системной папке, но если привычнее, чтобы папка `.venv` была
в корне проекта, то можно поменять это в настройках:
   ```shell
   poetry config virtualenvs.in-project true
   ```
4) Активировать виртуальное окружение (командой, которую вывел `poetry env actitvate`)
5) Установить зависимости 
   ```shell
   poetry install
   ```
6) Добавить в корень проекта файл `.env` (не пушится в гит, есть в .gitignore) - в нем можно хранить секреты (пароли и пр.) и переопределять настройки.
7) Прописать там DB_FILE_PATH - путь до mathematicon.db (от корня проекта) 

## Локальный запуск
Выполнить:
```shell
make start-app
```
По адресу http://0.0.0.0:8000/api/docs будет находиться swagger для API.

## Разработка
### Линтеры
В проекте используется ruff (как линтер и для форматирования), mypy (для проверки типов). 
Чтобы автоматически отформатировать код надо выполнить
```shell
make format
```
Чтобы прогнать линетры:
```shell
make lint
```

### Alembic миграции
При изменении структуры базы данных, нужно создавать скрипт миграции. 
Alembic может автоматически генерировать такие скрипты, сравнивая текущее состояние в базе и модели таблиц, описанных в коде.
В большинстве случаев он генерирует все правильно, но такие скрипты лучше проверять и при необходимости исправлять 
(например, при переименовании колонки или таблицы он сгенерирует drop а потом добавление, вместо переименования). 
Все скрипты находятся в migrations/versions. Для генерации новой миграции нужно выполнить:
```shell
make migration message="your migration description"
```
Накатить миграцию до самой последней версии:
```shell
make migrate-up
```
Откатить миграцию:
```shell
make migrate-down
```
